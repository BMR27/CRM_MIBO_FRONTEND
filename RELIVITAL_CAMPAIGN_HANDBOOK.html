Chapter 01

What this system is

A multi-channel CRM built around one WhatsApp Business number. Every customer message lands in a shared inbox, every customer is a contact record, and every outbound mass message is a campaign with its own code, recipient list and audit trail.

Three ideas carry the whole product. Learn them once and the rest of the interface explains itself.

Workspace

Your company is a workspace (internally, a tenant). Contacts, conversations, campaigns, agents and settings all belong to it, and nothing crosses between workspaces. Features are switched on per workspace, so a menu entry a colleague at another company describes may simply not exist in yours. Relivital also has its own private template that no other workspace can see or send.

Conversation

One continuous thread per contact. When a campaign message goes out, it is written into that same thread — so the agent who later picks up the reply sees the exact promotional text the customer received, not a placeholder.

Campaign

A single approved WhatsApp template, sent to many contacts in one operation, recorded under a generated code such as CMP-20261116094500. The code is what you quote in a meeting, paste into a ticket, or search for three weeks later.

Chapter 02

First login and the workspace

  1. Sign in

    Open the CRM URL and sign in with the email and password your administrator created for you. Sessions are per browser — signing in on your phone does not sign you out on your desktop.

  2. Let the guided tour run

    The very first time you open the CRM in a given browser, an interactive guide opens by itself: a module list on the left, numbered steps on the right. It appears once per browser, and you can reopen it any time from Guide at the bottom of the sidebar. This handbook is the long-form version of the same material.

  3. Set your language and theme

    In Settings → Appearance, choose light, dark or system theme, and set the interface language: Spanish, English, Polish or Russian. The choice affects the whole interface, including this manual's terminology. Polish matters here: the Relivital discount template is written in Polish for Polish customers.

  4. Check what your role lets you see

    Agents see conversations, contacts, campaigns and appointments. Supervisors additionally see Agents, Leads and Statistics. Administrators also get Settings; integrations and security panels are reserved for the platform super-admin. If a module named in this handbook is missing from your sidebar, it is either off for your workspace or above your role.

Chapter 04

Before you can send anything

Campaigns depend on three things being true. Confirm them before you spend an afternoon preparing a list.

RequirementWho arranges itHow you know it is missing
Bulk messaging enabled for your workspace Platform administrator The Campaigns entry is absent, or the send is rejected outright
A WhatsApp sender number connected to the workspace Platform administrator “WhatsApp is not configured for this workspace”
At least one approved template visible to you Meta approval + platform admin The template dropdown is empty or lacks the one you expected
Why templates at all

WhatsApp only lets a business open a conversation with a customer using a message template that Meta has reviewed and approved in advance. Free-form text is allowed only inside the 24-hour window that follows a customer's own message. That is why a campaign is always built around a template and never around a sentence you type on the spot — and why a brand-new template can sit pending for hours before it will send.

Chapter 05

Contacts: the recipient base

Campaigns can read recipients from your saved contacts, so the quality of the directory is the quality of your campaigns. Spend the time here, not in the send form.

Phone numbers are strict

Every WhatsApp number must be full international E.164 format: a leading +, a country code that does not start with zero, and 9 to 14 digits after it — no spaces, dashes or parentheses. The form normalizes spacing and adds the + if you forgot it, but it will reject anything that is not a plausible international number.

Written asVerdictReason
+48 12 420 73 49AcceptedSpaces are stripped automatically
+525512345678AcceptedCanonical E.164
5512345678RiskyA + is prepended, but with no country code it will not deliver
(55) 1234-5678RejectedPunctuation is not a digit
5.25635E+11RejectedExcel turned the number into scientific notation — see Chapter 08

Adding contacts one at a time

  1. Open Contacts and choose New

    Pick the channel first — WhatsApp or Facebook — because it changes the rest of the form.

  2. Fill the identifying field

    WhatsApp contacts need a name and an E.164 phone number. Facebook contacts need the page-scoped user ID (PSID) instead of a phone.

  3. Create, then chat

    The new contact appears in the list immediately. The chat action opens their existing conversation if there is one, and only creates a fresh thread when there is no history — so you never end up with two threads for the same person.

Bulk import from Excel

Contacts → Bulk import accepts .xlsx, .xls and .csv. The importer reads the first sheet and is deliberately forgiving about header names, so an export from another system usually works untouched.

FieldAccepted column headersRequired
Namename · nombre · Nombre · CLIENTE · ClienteRecommended
Phonephone_number · telefono · Teléfono · Telefono · PHONE_A · phoneYes, for WhatsApp
Channelchannel · canalNo — defaults to whatsapp
Facebook IDexternal_user_id · externalUserIdOnly for Facebook contacts
  1. Choose the file

    The CRM reads it in your browser and reports how many usable rows it found. Rows with neither a phone number nor a Facebook ID are discarded silently at this stage — if the count looks low, that is why.

  2. Review the count, then import

    Nothing is written until you press Import. The result tells you three numbers: created, updated and failed.

  3. Understand “updated”

    A row whose number already exists updates that contact instead of duplicating it. Re-importing a corrected list is therefore safe and is the normal way to fix a batch of bad names.

Chapter 06

Templates and their variables

A template is fixed text with numbered slots — {{1}}, {{2}}, {{3}} — and each slot is mapped to a named field the CRM fills per recipient.

Which templates you can see

Workspaces with a dedicated template see only their own; everyone else sees the shared defaults. Relivital is in the first group, which is why the Relivital discount template is the only option in that workspace rather than one option among three.

TemplateLanguageSlots → fieldsVisibility
customer_service_intro_v1 es_MX 1 CLIENTE · 2 ASESOR · 3 PRODUCTS_A Shared default
pedido_enviado_v1 es_MX 1 TOTAL_PEDIDO · 2 TRACKING · 3 PAQUETERIA Shared default
relivital_descuento20_v2 pl 1 CLIENTE · 2 FECHA_LIMITE Relivital only

Fields the CRM fills for you

Three names are resolved automatically and never appear as something to type:

  • CLIENTE — the contact's name, from the selected contact or the Excel row.
  • PHONE_A — the destination number, same source.
  • ASESOR — the signed-in agent's name; if it is somehow blank, the template's own fallback is used, so a send is never blocked on it.

Everything else is an extra field: PRODUCTS_A, TOTAL_PEDIDO, TRACKING, PAQUETERIA, FECHA_LIMITE. Extras are the single most common cause of a blocked send, and Chapters 07 and 08 show the two ways to supply them.

Version note

The Relivital template ends with a deadline the customer must beat. In v1 that date was baked into the approved text; v2 promotes it to {{2}} = FECHA_LIMITE, so the same template can be reused every month by typing a new date. A freshly submitted version cannot send until Meta approves it.

Chapter 07

Campaign A — sending to saved contacts

The route to use when the recipients already live in your CRM: a hand-picked segment, a follow-up to last week's buyers, a retry to a handful of people. One value per extra field applies to the whole batch.

  1. Open Campaigns and press New campaign

    The composer opens above the history table: the form on the left, a live summary panel on the right. Nothing is sent until you press Send in that panel.

  2. Name the campaign

    Use something you will recognize in a list of fifty — “Polish customers · November 20% discount”. Leave it blank and the CRM names it after the template plus the generated code, which is accurate but anonymous.

  3. Choose the template

    Only templates visible to your workspace are listed. The summary panel on the right immediately shows the full approved text with its slots in place, so you can read exactly what the customer will get before committing.

  4. Fill the template's extra fields

    If the template has extras, an input appears for each one. Whatever you type applies to every recipient in this campaign — that is the defining limit of this route. One date, one courier, one product name for the whole batch.

  5. Switch the recipient source to Saved contacts

    This is the default. Only WhatsApp contacts are listed; Facebook contacts cannot receive a WhatsApp template and are filtered out of the picker entirely.

  6. Search, then tick

    The search box filters by name, number or contact ID. Select filtered ticks everything currently matching — the fast way to take a whole segment — and Clear selection empties it. Two counters under the box keep you honest: how many are selected, and how many are visible under the current filter. They are different numbers, and the one that matters is selected.

  7. Add internal notes

    Optional, never sent to anyone. This is where the segmentation reasoning belongs: “bought in September, no reorder since”.

  8. Read the summary panel, then send

    The badge shows the recipient count, and the first twenty names and numbers are listed beneath the template text. Check that count against what you intended. Then press Send now — the button stays disabled while there are no recipients or no template.

Blocking rule

On this route, every extra field must be filled before anything is sent. Leave one empty and the send stops with “Enter the field FIELD…” — no partial batch goes out. If different recipients need different values, that is the Excel route, not this one.

Chapter 08

Campaign B — sending from an Excel file

The route for large lists, for people who are not in the CRM yet, and — crucially — for campaigns where each recipient needs their own values: their own tracking number, their own order total, their own deadline.

  1. Pick the template first, then download its spreadsheet

    With the template selected, press Download Excel. The file you get is generated for that specific template: a header row of exactly the columns it needs, plus one example row. Never build the sheet from memory — the headers are the contract.

  2. Understand the columns

    Column 1 is always CLIENTE, column 2 is always PHONE_A, and after them comes one column per extra field. For pedido_enviado_v1, that means CLIENTE, PHONE_A, TOTAL_PEDIDO, TRACKING, PAQUETERIA.

  3. Fill one row per recipient

    Delete the example row. Every row must have a destination number and a value in every extra column — a blank cell anywhere stops the whole send.

  4. Format the phone column as text

    This is the one Excel habit worth drilling. Select the phone column, set the cell format to Text before pasting, and keep the leading +. Left as a number, Excel displays long numbers as 5.25635E+11 and strips the +. The CRM defends against this — it reads the underlying numeric value rather than the displayed text, and converts whole numbers back to digits — but a number that lost its country code cannot be recovered by anyone.

  5. Let dates be real dates

    A date cell is read as a date and rewritten as DD/MM/YYYY before it reaches the message, so the customer never sees an Excel serial number like 46368. Either a true date cell or plain text works; what fails is a date typed into a cell someone pre-formatted as General and then switched to Number.

  6. Switch the recipient source to Excel and upload

    In the composer, flip the recipient toggle from Saved contacts to Excel and choose the file. Only the first sheet is read. .xlsx, .xls and .csv are all accepted.

  7. Verify in the summary panel

    The badge count must match your row count, and the preview list must show real names against real numbers. A count that is one too high usually means the example row is still there; names reading “undefined” mean the header spelling drifted.

  8. Send

    The per-recipient extra-field inputs are not used on this route — the spreadsheet supplies those values row by row. That is the whole point of choosing it.

Which route, when

Saved contacts — the segment is already in the CRM and one set of values fits everyone. Excel — the list is long, the people are new, or each recipient needs different values. A useful third pattern: import the sheet through Contacts first so the people are permanently on file, then run the campaign from saved contacts.

Chapter 09

What happens the moment you press Send

Knowing this sequence is what lets you read a half-finished result and know exactly where it stopped.

  1. Local checks, before anything leaves your browser

    A template must be chosen, there must be at least one recipient, and on the saved-contacts route every extra field must be filled.

  2. Row-by-row validation — the blocking stop

    Every recipient is checked against every slot in the template. The first row missing a value with no fallback aborts the entire campaign, and the message names the offending person and the field. Nothing has been sent at this point — fix the row and send again with no risk of duplicates.

  3. The campaign gets its identity

    A code is minted from the current timestamp — CMP-YYYYMMDDHHMMSS — alongside an internal ID. If you left the name blank, it is composed now from the template name and that code.

  4. The server processes recipients one at a time

    For each one, in order: find the contact by number or create it; find their conversation or open one assigned to you; resolve the slot values; send through WhatsApp; then write the fully rendered message — real values, no placeholders — into the conversation, tagged with the campaign code.

  5. Failures are isolated, not fatal

    Past validation, a recipient who fails (unreachable number, provider rejection) is recorded as an error and the loop moves on. One bad number does not cost you the other 199.

  6. The result banner appears

    Green, at the top: the code, how many of how many were sent, how many failed, and the first error text if there was one. The composer then clears itself and the history reloads. Read the banner before you leave the page — it is the most compact account of what just happened.

Side effects worth knowing

A campaign to people who were not in the CRM creates those contacts and opens conversations assigned to you. Replies will land in your inbox. Plan capacity for a large send accordingly — a 500-person campaign is also 500 potential conversations on your desk.

Chapter 10

Tracking, filtering and auditing

The five metric tiles

The tiles at the top of Campaigns describe the filtered set, not all time. Narrow the dates and the tiles narrow with them — which makes them a reporting tool, but also means a tile is never an all-time figure unless the filters are cleared.

TileCounts
CampaignsCampaigns matching the current filters
RecipientsTotal intended recipients across those campaigns
SentMessages successfully handed to WhatsApp
FailedMessages rejected per recipient
ActiveCampaigns still scheduled or sending

Statuses

StatusMeaningNormal next step
ScheduledQueued, not yet startedWait
SendingWorking through the recipientsRefresh in a minute
CompletedFinished — possibly with some failuresOpen View and check the failed rows
FailedFinished with failures and zero deliveriesTreat as systemic: sender, template or number format

The distinction is deliberate and worth internalizing: a campaign is only marked Failed when nothing at all got through. Mixed results stay Completed, so the failure count in the row — not the status pill — is what you check after every send.

Finding a campaign again

  • Search matches the campaign name, its code, and the template name.
  • Date range opens at the first of the current month through today. Widen it before concluding that an older campaign has vanished.
  • Status and Template narrow further; Clear resets everything to that default month window.

The three row actions

  1. View

    Opens the recipient-level detail below the table: contact, number, status (sent, skipped, failed), date, and the complete message that person received. This is your evidence when a customer asks what you sent them.

  2. Copy

    Copies the campaign code to the clipboard for a ticket, a report or a message to support.

  3. Delete

    Removes the campaign from the history behind a confirmation dialog. It deletes the record — messages already delivered to customers are gone from your reports, not from their phones.

Two histories, one table

Recent campaigns are also cached in your browser so the list is never empty after a send, and that cache holds the last 100. Campaigns sent from another computer or another browser appear only once the server history loads — so if a colleague's campaign seems missing, press Refresh before raising it.

If you are unsure whether a send happened

Do not immediately resend. Press Refresh, look for a campaign code with the current timestamp, and open View to see which recipients already have a message. Resending blindly means customers receive the same promotion twice, and on WhatsApp that is a reported-as-spam risk for the whole number.

Chapter 12

Pre-flight checklist

Run this before any campaign above roughly fifty recipients. It takes two minutes and has prevented every expensive mistake in this chapter list.

  • The template selected is the one approved for this campaign, in the right language for these recipients.
  • The message preview in the summary panel has been read end to end, including the final line.
  • Extra fields are filled — in the form if one value fits everyone, in the spreadsheet if they differ per recipient.
  • Any date value is written in the format the customer expects, and the deadline is still in the future.
  • The phone column is formatted as text, every number carries its country code, and none shows as 5.2E+11.
  • The example row from the downloaded template has been deleted.
  • The recipient count on the badge matches the number of people you intended to reach.
  • The campaign has a name you will still recognize in three weeks.
  • A test send to your own number has been made and checked on a real phone.
  • Someone is available to handle the replies this campaign will generate.

After the send

  1. Read the green banner

    Record the campaign code. Note the sent-of-total figure and any failures.

  2. Open View on the new row

    Scan the failed recipients. Failures clustered on one country code point at number formatting; scattered single failures are usually numbers that are not on WhatsApp.

  3. Fix and re-run narrowly

    Correct the bad numbers in Contacts, then run a second small campaign for just those people — never re-run the full list.

  4. Watch the inbox

    Replies arrive in Conversations on the same thread as the campaign message, so the agent answering sees the exact text that prompted the reply.
